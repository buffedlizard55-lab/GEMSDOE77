<h2>Why the portal error happened — and how we fixed it</h2>
<p>DrivenData rejects a submission whose values fall outside <code>[0,1]</code>, and it also rejects a raster whose <b>nodata tag</b> is a large negative sentinel such as <code>-3.4028234663852886e+38</code>, because that sentinel is not a value in <code>[0,1]</code>. Two mechanisms produced the same message:</p>
<ul>
<li><b>Mechanism 1 — float32 sentinel:</b> <code>training_features.tif</code> uses <code>-3.4028234663852886e+38</code> as nodata: 7,113,308 cells, 3,061 inside footprint if written through unchanged.</li>
<li><b>Mechanism 2 — NaN sentinel:</b> a raster with <code>nodata=NaN</code> and NaN outside footprint is legal per spec but one validator change away from the same rejection.</li>
</ul>
<p><b>Fix verified by re-reading written bytes:</b> every GeoTIFF offered here is single-band float32, EPSG:32611, 100 m, 3730×3292, every cell finite, min 0.0 max 1.0, zero NaN, no nodata tag (zeros variant) or nodata=NaN with NaN outside (nan twin). Each ships a <code>-audit.json</code> receipt from re-opening the file.</p>
