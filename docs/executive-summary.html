About the earlier “Predicted values must be in range [0, 1]” error

The original rejected bytes/organizer diagnostics are unavailable, so the cause is not proven. The pinned shared writer refuses non-finite or out-of-range values rather than clipping them, writes a single float32 band with no nodata sentinel, and re-opens its output to check the sample's CRS/shape/transform. For the linked H77L file, the read-back range is [0.0, 1.0], zero NaNs inside the footprint and anywhere else, and zeros outside the template's finite footprint (see validator receipt). This removes the measured local risk of out-of-range pixels; it is not an organizer acceptance guarantee and does not override NOT OK TO SUBMIT.
