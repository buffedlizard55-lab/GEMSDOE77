Executive summary: exactly how to submit

  1. Download the .tif from the green box above. Do not rename it.
  2. Sign in at DrivenData. Open the competition's Submissions page (requires login; this is the official URL).
  3. Upload the .tif, or the one-TIFF .zip, but only one of them. Each upload uses one of your weekly submissions. The website limit prevails over the rules' parenthetical "three per week" (DrivenData staff, forum 11553).
  4. Paste the note from the box above (it is optional and 113/140 characters), then submit.
  5. Record the public score next to the file name and its sha256 (a8bfb844ab44b5d4…). A new score feeds directly back into the live inversion (registry/live_scores.csv).

Why the portal said "Predicted values must be in range [0, 1]"

We measured two mechanisms from the official inputs.

  1. The training_features.tif nodata sentinel (−3.4×10³⁸) appears in 3,061 cells inside the scoring footprint. Left in, these are out-of-range values.
  2. A footprint taken from feature band 1 instead of sample_submission.tif leaves those cells as NaN inside the scored region.

The shared template's own validator uses the band-1 footprint (reported as a template fix in the analysis). This file avoids both mechanisms: no NaN anywhere, no sentinel, and the official footprint.
