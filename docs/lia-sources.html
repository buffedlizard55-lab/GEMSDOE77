Irregularities flagged

  1. IR-77-01: the brief's "single method paragraph below" (the lane) is missing. The lane was self-assigned and disclosed.
  2. IR-77-02 (historical note): supplied leaderboard values 0.4413 and 0.3195 conflict. This review did not fetch the official leaderboard; do not present either as current. The pinned GEMSDOE32 owner page records 0.3195 in a dated 2026-10-04 snapshot and disclaims scores for its own artifacts.
  3. IR-77-03: entries in registry/live_scores.csv are OWNER-REPORTED. No organizer receipt tying 0.2778 to the H33 TIFF was found; the pinned GEMSDOE32 page says no organizer score exists for artifacts in that repository.
  4. IR-77-04: under the literal reading, the 70% overlap rule fires on any raster when the registry contains space-filling surfaces. The template's like-for-like reading (dot fields only) is applied, and both readings are reported in evidence/e3_uniqueness.json.
  5. IR-77-05: the shared template validator uses a band-1 footprint (see the analysis, §8). Patch proposed; vendored bytes untouched.
  6. IR-77-06: GEMSDOE71's vendored template has a locally modified grid.py; this repo re-vendored the upstream bytes.
  7. IR-77-07: the hide-and-recover holdout measures recovery of catalogue faults, and it mis-ranked live outcomes in earlier runs (GEMSDOE66/70/71). It is used as a required gate, not as a score predictor.
  8. IR-77-08: sample_submission.tif carries 1.0 on the 60,988 catalogue pixels. It is not the "total absence" example the page describes. Only its grid is used.
  9. IR-77-09: GEMSDOE73–82 were empty at the start of this session. Some have since gained files (parallel sessions) and are not in the registry snapshot.

Limitations and access needs

  • The DrivenData data page and submissions are login-gated. Inputs come from the owner's GitHub mirrors and are sha256-pinned (registry/data_manifest.json, evidence/restore_receipt.json). A pin proves mirror consistency, not organizer authenticity.
  • Raw raw.githubusercontent.com, Dropbox and drivendata.org downloads are blocked in this sandbox. Files are fetched through the GitHub blob API.
  • The live inversion assumes the public chunks are a spatially random subset, and it cannot evaluate locations that no scored raster covered.
  • No weekly slot was used. A human (the selector) must upload.
