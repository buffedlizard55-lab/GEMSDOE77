2. Mechanism

DTI = T / (0.2 (T + S − Mk) + 0.8 K). Each dot adds a fixed α to the denominator, so it pays off only if its kernel credit exceeds α·DTI (≈ 0.058). Kernel credit is a max, not a sum, so binary dots spaced about 3 px apart are near-optimal. Known-fault pixels are masked from scoring, and test truth contains only faults not in the catalogue.

4. Can it be beaten?

Without the uniqueness rule: yes, modestly. Pruning the dots that fall below the bar helps. Under the rule: very likely not, with the fields known today. The 3 px overlap radius equals the kernel radius, so at least 30% of a unique raster's dots must earn credit more than 3 px from H19-5. To tie the champion, those dots need at least 0.056 credit each. Neither tested off-support field improves the leave-one-out fit.

8. Shared-template issues (reported; no private fork)

  • gems.validate_submission takes the footprint from feature band 1 (5,165,852 cells) instead of sample_submission.tif (5,167,373 cells). A correct NaN-outside file then "fails" with 1,540 NaN inside and 3,061 finite outside. A file built to pass it leaves 3,061 scored cells as NaN, which is one portal-rejection mechanism. Proposed upstream patch: reports/template_fix_validate_footprint.patch.
