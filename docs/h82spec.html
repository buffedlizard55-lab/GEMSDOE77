Why this is a genuinely new technique in this repository

Every prior GEMSDOE77 lane that touched magnetic/gravity depth used a spatial-domain method: Euler deconvolution with structural index 0 and upward-continuation phase persistence (H77E, negative, below random); tilt zero-crossings, analytic-signal ridges, monogenic phase congruency and pseudogravity-Poisson slope (contact-physics, negative); magnetite-destruction trough and gravity-basement step (H77G, negative). H82S is the first frequency-domain method: it azimuthally averages the 2-D radial power spectrum of RTP inside each 3.2 km block and fits the classical Spector & Grant (1970) single-slope relationship ln(amplitude) ≈ ln(C) − z·k to estimate z, the depth to the statistical ensemble of magnetic sources under that block, then takes the spatial gradient of the resulting depth surface as the candidate fault-edge signature. A repository-wide grep -ril "curie|spectral centroid|power spectrum" before this lane found only one prior mention (research/hypotheses-xsen-2026-10-21.md), which rejected the idea on the mistaken premise that it needs a new external heat-flow compilation — corrected in research/h82spec_hypotheses.md: the single-slope estimate needs only the cached, already-restored RTP band.

Synthetic correctness check before trusting the real-data run

Before running the method on the GeoDAWN RTP band, tests/test_h82spec.py builds a synthetic field whose known radial amplitude spectrum decays as exp(-k·z_true) for a chosen z_true = 600 m, feeds it through the exact same block estimator, and checks the fitted depth lands within a factor of two of the true value. Both synthetic unit tests pass, so the arithmetic itself (radial binning, slope fit) is verified correct independently of whether the resulting real-data feature turns out to be predictive (it did not).
