What was tested, in one paragraph

The scored truth set is faults ABSENT from the USGS/INGENIOUS catalogue, so allocating the dot budget by the positive residual of a censored catalogue-intensity model (predicted fault-pixel count per 2 km block minus the visible count) recovers withheld fault segments better, at equal budget, than allocating by the per-pixel fault-likelihood surface alone.

Mechanism. Poisson-loss gradient-boosted regression of mapped fault-pixel rate per 20x20 px block on block-aggregated physics; deficit D(b) = max(0, lambda_hat(b) - n_visible(b)); D smoothed to pixels, normalised to [0,1] and multiplied into the per-pixel surface before the shared 300 m submodular allocator.

Named non-fault process that could mimic it. Eroded volcanic tableland edges, pluvial Lake Lahontan shoreline terraces and Tertiary tuff lithologic contacts raise the predicted intensity in blocks that contain no faults at all. The hide-and-recover design itself manufactures the local mapping deficit the lane detects, so the holdout is optimistic for this lane relative to a live organizer score.

Irregularities raised by this lane

IR-H82FMD-01 (shared tool, fixed upstream): vendor/gems57/uniqueness.py could not report which registry comparators are too dense for a 3-px overlap test to carry information. Added _disk_area() and space_filling_flags() as reporting helpers. Integration moved them to gems82fmd.registry_diagnostics to restore the pinned shared template; no gate is forked or changed — so both readings are always published. No threshold or verdict was changed.
IR-H82FMD-02 (budget overrun, declared in advance): E4 is a fourth experiment against a 3-experiment budget. It was preregistered in registry/preregistration_h82fmd_amendment_e4.json before it ran, and it is reported as an overrun rather than hidden.
IR-H82FMD-03 (documentation): the preregistration says 27 physics channels; the implementation builds 28 (fields.CHANNELS). The extra channel is valley_s1p5, present in the code from the first commit of the lane and in every arm including the controls, so no comparison is affected. The count in the prose was simply wrong.
IR-H82FMD-04 (numerical, measured and pinned): non-maximum suppression keeps ties, so in a region that is flat to within float32 noise every pixel survives thinning. On the real surface that is 25 pixels out of 1,065,169 (0.0024%), all with surface <= 0; the lane allocates against surface × crest, so they carry zero weight and cannot attract a dot. The function was deliberately not re-tuned after E3/E4 had been measured with it.
IR-H82FMD-05 (protocol): the 3-px dot-overlap gate cannot distinguish duplication from blanket coverage when the comparator emits 10% of the map. This lane fails that gate and is published as research-only anyway, with the density breakdown beside it as a diagnostic — the rule is applied as written, not rewritten after seeing the number.
