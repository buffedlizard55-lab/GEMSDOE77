## What the archived lineage suggests

The owner-mirror forensic record describes a sequence built from one H19-5 ridge surface: 121,131 dense pixels, then 60,069 and 44,090 thinned dots, then 40,199 and 37,654 after progressively excluding dots near mapped catalogue traces. The corresponding family-reported scores rise from 0.1922 to 0.2477, 0.2600, 0.2708, and 0.2778. These are sequential, owner-reported results, not a controlled experiment: the ordering is compatible with a useful metric-aware design, but does not isolate causality or authenticate any file-to-score mapping.

The plausible metric mechanism is **reduced redundant prediction mass**. The local pinned evaluator uses a 300 m triangular kernel, with `α=0.2`, `β=0.8`; nearby predictions can cover the same truth pixels while each still contributes false-positive cost. Spacing a ridge into dots near the kernel radius may preserve much of the coverage while reducing redundant mass. Removing dots near already mapped faults may help for the initial-round target if those locations mostly represent mapped structures rather than new ones. Neither statement proves that a particular removed pixel was false, that hidden faults begin at a specific catalogue distance, or that these operations caused the reported public score.

## Exact marginal condition (including redundancy)

Let `T` be weighted true-positive credit, `F` weighted false-positive mass, `K` withheld truth pixels, and `s = T / (T + αF + β(K−T))` the current DTI. For an added binary dot, let `k` be its kernel weight to the nearest truth pixel and `dT` be its **marginal** increase in `T` (which can be smaller than `k` if earlier dots already cover those pixels). With `α+β=1`, the denominator changes by `α(dT + 1 − k)`. The exact improvement condition is:

```text
dT > α · s · (dT + 1 − k)
```

Only for a non-redundant dot, where `dT = k`, does this reduce to `k > α·s`. At `s=0.2778`, that special case gives a kernel-weight threshold of about `0.0556` (roughly 283 m from truth under the idealized isolated-dot geometry). It is not a universal placement rule for redundant dots. This is consistent with the shared implementation in `vendor/gems57/metric.py`; do not use the simplified threshold as evidence about the unknown hidden labels.

## What would be required to beat the reported value

A more efficient emitter can remove avoidable redundancy, but cannot create geological information absent from its ranking surface. A credible attempt to improve would need a genuinely better off-catalogue field, then a preregistered, buffered whole-segment spatial holdout using the pinned evaluator, feature-alone leakage canaries, pre-placement registry checks, and a matched baseline. Even that would be **HOLDOUT-DTI**, not a public-score prediction. A new file would still need a complete literal registry pass and separate selector approval before any slot decision.

No such experiment or slot decision was made in this repository review. The dense-witness record and zero-file authorization receipt remain operative blockers. A claim that GEMSDOE77 has beaten the H33 public score, or will beat it, is not supported.
